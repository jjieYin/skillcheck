# Skill 哈希与特征哈希向量对照实验

日期：2026-10-02

## 目的

验证当前 `content_hash`、`instruction_hash` 和默认 256 维特征哈希向量，能否稳定地区分以下情况：

- 完全相同的 Skill；
- 只有元数据或排版变化；
- 只有资源文件或执行脚本变化；
- 核心规则由肯定变为否定；
- 真实的完整版/轻量版 Skill；
- 无关 Skill 被相同公共模板污染。

本实验只建立当前算法基线，不修改生产判定逻辑。

## 样本选择

受控样本以 `systematic-debugging` 6.4.1 为基础，生成完全复制、metadata 变化、排版变化、附件变化、脚本变化和否定规则六种单变量变体。

真实 Skill 对：

- `systematic-debugging` 6.4.1 / 6.4.2；
- `opt-sub-api-to-debug` / `opt-sub-api-to-debug-lite`；
- `case` / `test-analysis`；
- `case` / `case-writer`；
- `systematic-debugging` / `opt-sub-api-to-debug` 作为无关对照。

公共模板实验使用原本无关的 `systematic-debugging` 和 `case`，分别在原文后加入同一段重复模板。

## 已确认的问题

1. `instruction_hash` 包含全部 frontmatter。只增加不影响行为的 metadata，就会改变指令哈希。
2. `instruction_hash` 不包含脚本。展示附件变化和执行脚本变化都会得到同样的“指令相同、包不同”结果，无法区分行为影响。
3. 特征哈希向量几乎忽略局部否定。核心规则由 `ALWAYS` 变为 `NEVER` 后，三个维度的相似度仍约为 0.9997。
4. 公共模板可以主导长文本相似度。两个原本无关的 Skill 加入相同模板后，相似度超过当前 0.86 的重叠阈值。
5. 增大向量维度只能降低一部分哈希碰撞噪声。无关对照从 256 维的 0.0724 降至 4096 维的 0.0051，但否定规则和公共模板问题没有消失。
6. API 联调完整版与轻量版是明确的同族变体，当前综合分数为 0.8310，却因为缺少环境变体信号且低于 0.86 重叠阈值而返回 `PASS`。

因此，主要根因是参与哈希的语义边界不合理，以及整篇文本的词频/字符片段表示和单向量汇总方式不足。256 维碰撞是次要问题，单纯增加维度或调整阈值不能解决核心误差。

## 实验边界

当前环境没有安装 `sentence-transformers`，本轮没有下载外部模型，因此没有将当前结果与多语言语义模型直接比较。实验结论只针对现有包哈希、指令哈希和特征哈希向量。

## 下一步建议

先把上述失败样本固化为算法验收数据集，再分别验证两项改动：

1. 将哈希拆为包内容、行为指令、执行依赖三个指纹；
2. 将触发描述、步骤、约束和输出分段表示，公共模板降权，并保留否定与强制词特征。

只有新算法在这些固定样本上通过后，再比较多语言 embedding 和 reranker，避免用模型或阈值掩盖哈希边界问题。

复现实验脚本：`scripts/experiments/hash_vector_baseline.py`。
